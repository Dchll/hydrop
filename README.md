# hydrop

局域网文件传输软件

## 依赖
- Flutter 3.41.9
- Drift
- Dio
- AutoRoute
- Riverpod

## 规划新增依赖

- `network_info_plus: ^8.1.0`：补充 Wi-Fi IP、网关、子网掩码、广播地址等网络信息，用于设备发现。
- `cached_network_image: ^3.4.1`：为 `ImageWidget` 的网络图片分支提供磁盘/内存缓存、占位和错误态能力。

## 功能分析

- 当前代码已经具备清晰的数据基础：`lib/data` 只保留 `local` 和 `remote` 两个顶层边界，本地能力通过 Drift + Repository + Riverpod 暴露，适合继续把发现、连接、消息都落成可测试的数据流。
- 已完成的能力主要是“基础设施”和“本地持久化”：主题、每日一图、设备表、消息表、附件表、设置表都已成型，但多数产品功能还停留在数据层或页面骨架阶段。
- 最大缺口在网络层：本机地址枚举、UDP 广播、点对点连接、心跳、测速、重连、传输协议目前还没有统一抽象；这些能力会直接决定设备列表、连接保持和消息收发能否真实可用。
- 消息功能应按“文本先闭环，媒体后扩展”的顺序推进。文本消息验证协议、会话状态、失败重试和历史记录后，再复用附件表扩展图片、视频和其他文件。
- 设备记忆不应只存设备 ID，还需要存设备的多地址历史、可用性、测速结果和最后见到时间；否则无法实现“当前可用速度从快到慢、不可用保留历史”的排序要求。
- UI 层需要避免直接操作 Drift 或网络细节。页面只消费 provider 暴露的状态，发现、连接、消息发送等副作用放到 repository/service 层，保持可测试和可替换。
